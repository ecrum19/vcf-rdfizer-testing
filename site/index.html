RQ1 Which aspects of VCF information are preserved and verifiable?

Source comparisons and structural validation provide complementary evidence.

VCF-RDFizer's validation layer answers questions () of each graph in SPARQL and again, independently, from the source VCF with cyvcf2, and SHACL shapes check structure the questions do not observe. The base campaign ran paired validations: difficult-input fixtures, a small fixture under both sample profiles and three RDF artifacts, and HG005 slices up to triples. A fault-injection experiment applies deliberate corruptions, and a later run validates a consumer WGS VCF with the default shapes.

Consumer WGS validation run: , first records

What the evidence shows

Across the base campaign, of paired comparisons were exactly equal after normalization; the other are genotype questions verified not applicable to files without genotypes. Every engine that answered agreed. This establishes representation equivalence for the fields the questions cover, not that the source calls are biologically correct.

The two layers catch different defects. The source-comparison questions miss of the injected faults, in classes they cannot observe, such as which allele a genotype calls or a header attribute's value. The default shape profile, the only one practical at scale, catches none of them; all shape profiles together catch every one, but have not been shown practical for a complete VCF.

On a consumer WGS VCF converted to triples, all thirteen answers equal the VCF's, and the default shapes, checked in record batches, report no violations.

RQ2 What does the explicit representation in RDF enable in a linked, policy-aware workflow?

Shared identifiers enabled reusable joins and verified release views.

Which participant–variant–gene matches connect an observed allele to a ClinVar classification in the -gene set, and which matches may each requester receive? Two routes answer it and must agree: an RDF route (SPDI and gene links, one checked release view per requester, one SPARQL query per view) and a conventional bcftools route that applies the same rules in Python. Arm 1: gene-span slices of single-sample VCFs (). Arm 2: 1000 Genomes participants. Arm 3: the complete VCF. Arm 4: the complete VCF under layered consent, with requesters. Consents are simulated; the VCFs are real and public. Every stage ran VCF-RDFizer .

Released records: each release view against the conventional route

Linking: calls linked to shared identifiers

What the workflow shows

In all arms the RDF and conventional routes returned identical requester-specific match sets, and every release view passed its policy and source checks. Released-record counts also agreed in . In , the RDF views released more records to disease-specific and general research: symbolic structural variants in restricted genes, which the release links to no gene. No match changed.

Explicit links did not mean fewer lines: realistic changes were data edits of similar size in the table-driven conventional pipeline. The difference is where a rule lives. A consent or cohort rule becomes a statement beside the data that a query can ask about and a check can verify against the VCF text, and a rule on one variant's SPDI identity holds whatever a file calls its chromosome.

The cost is paid before the first answer: conversion, linking, view writing and indexing. Queries took seconds across the arms, because the fixed ClinVar join dominates them; this does not show that SPARQL performance is independent of scale.

RQ3 Under which workloads and representation choices are the costs practical?

Semantic coverage and practical cost depend on representation and workload.

Semantic coverage across converters

VCF-RDFizer and other executable converters convert the same inputs. The content questions are ported to each vocabulary and compared with the same source-derived oracle, so a cell differs only because the graph lacks or transforms the information.

Conversion cost

Controlled ladders vary one dimension at a time: records on HG005, and sample columns on a fixed set of 1000 Genomes records. The storage mode and the optional HDT and COTTAS artifacts trade disk and time.

Retrieval cost

The same questions answered by SPARQL and by cyvcf2 parsing the VCF, with every answer compared before any timing was read; the SPARQL engines and artifacts against each other; QLever on graphs up to the complete HG005 VCF; and region-restricted questions against a tabix-indexed VCF.
